搭这个博客的时候，我给自己定了一条规矩：不装 Node.js，不装 npm，不引入任何外部 CDN，也不加构建工具。

写下来之后我发现，这条规矩几乎没有让我损失什么。

## 省下来的东西

最直接的是**没有 `node_modules`**。不用等依赖下载完，不用担心某个包两年没更新，不用处理版本冲突，也不用定期升级一堆我根本不知道做什么用的东西。

其次是**没有构建步骤**。我改了 `assets/style.css`，推送，结束。

## 一个真实的例子：配色

我想把模板原来的粉色系换成偏青绿的颜色，本来以为要翻遍整个样式表。实际上只需要改文件开头这一块：

```css
:root {
  --ink: #1b2a33;
  --accent: #1d7a6f;
  --paper: #fbfaf6;
}
```

因为原作者把所有颜色都定义成了 CSS 变量，其余规则都在引用变量。**这就是原生 CSS 变量能做的事**，不需要 Sass，也不需要 PostCSS。

## 那什么时候才需要构建工具

我现在的理解是：当你**真的有**这些东西的时候——

- 组件在多个页面之间大量复用
- 需要 TypeScript 这类必须编译的语言
- 有几十个页面，手工维护导航会出错

而我只有几篇文章和一个首页。为这个规模引入工具链，工具本身就会变成项目里最复杂的部分。

## 一点保留

这不是说构建工具不好。我以后要是做一个交互复杂的小应用，大概率还是会用它。只是对**写文章**这件事来说，它解决的不是我的问题。
